Guidance for working in this repo. Read this fully before making changes.

## What this is

Bhasaly (formerly Sajilo Nepali; भाषा bhasa = "language") is a **single-file
HTML** language-learning web app, faith-forward (Christian ministry context).
Everything — HTML, CSS and the whole engine — lives in `index.html` (~220KB);
course data lives in per-language packs under `lang/`.

- Live at **bhasaly.com** (Netlify; **sajilonepali.com** 301-redirects to it,
  both whitelisted in Supabase Auth). Keep sajilonepali.com registered.
- **Netlify auto-deploys on every push** (~15 credits each) — batch work,
  push rarely, and see Git / deploy below.
- **Supabase** handles login + progress sync (keys already in the HTML —
  don't touch).
- Owner: Ruan (Mac user, no Node — see Validation). Prefers highly specific,
  actionable help.
- **Status (July 2026): ELEVEN courses COMPLETE at 12 zones each** — see the
  course table below — plus the Nepali Language Intensive track, the
  Religious studies mode (all 11 languages translated), and the Bengali
  Short-term phrasebook. No course carries an early-access label.

## Golden rules

1. **Always work directly on `index.html`.** Edit it in place; keep that
   exact filename (Netlify serves it as the site root).
2. **Never break any shipped language.** Changes to the Intensive track must
   leave the main course provably untouched; new-language work must leave
   every shipped pack provably untouched (see Validation step 5).
3. **Validate before committing** (see Validation). Never commit a build that
   fails the parse check or the smoke test.
4. **Regenerate a language's audio strings file whenever spoken content
   changes**, then run `generate_audio.py` for that language and commit the
   new clips + manifest (see Audio).
5. Keep the UI minimal and uncluttered. Faith-forward but never preachy in
   mechanics.
6. **DEPLOY ONLY WHEN RUAN SAYS SO.** Never `git push` on your own judgment —
   commit locally as work completes and wait for an explicit "deploy"/"push".

## Architecture

**Boot.** No pack is present at parse time. An async `boot()` at the end of
the script reads the saved language (`savedLang()`, which also understands
the pre-split `sajilo` blob), fetches ONLY that pack via `loadLangScript`,
then `applyPack` + UI build. Missing/unknown pack → `ne`; if that fails too,
a plain retry message. **The `?lang=<code>` deep-link** (from the landing
pages): a known code overrides `savedLang()` AND forces `S.mode='learn'`;
unknown codes are ignored. Adding a language changes nothing about boot.

**Routing (July 2026).** The query string is the app's URL state: `lang`
(the landing-page contract), `v` (the view), `s` (which faith story).
`show()` ends in `pushRoute()`; a `popstate` listener restores the view.
**A view implies its mode** — that is what lets faith mode survive a reload
without the bare-`?lang=` force-to-learn rule firing, so `?v=` overrides it
in boot. **`navLock` means "navigation restored, not chosen"** (boot,
popstate): it suppresses both the history push and the `mode_switch` event.
Back out of a lesson exits without the ✕ confirm — deliberate. Query params
rather than pretty paths on purpose: no Netlify rewrite, so nothing can
shadow the static `/learn-<slug>` pages.

**Analytics.** `track(name, props)` speaks both Umami and Plausible and is a
**no-op until a provider script is uncommented in `<head>`**. Event list and
the privacy rule live in `GROWTH.md` — **props are language codes, lesson
ids and counts ONLY; never an email, free text or an answer.** Adding an
event means updating that table too.

**Supabase loads on demand.** No static `<script>` tag: `loadSupabaseLib()`
injects it only for a stored session (`sb-<ref>-auth-token`), a magic-link
callback (`?code=` / `#access_token=`), or the user opening the login modal.
Anything needing a client must `await ensureSupabase()` — never assume `sb`.
`sbFailed`, not a null `sb`, is what means "sync unavailable".

**Language packs.** Data consts (`XX_LESSONS`, `XX_UNITS`, `XX_SYM`,
`XX_VOWELS/CONS/NUMS`, `XX_SRS_SEED`, art) bundle via `registerPack({code,
name, nativeName, ttsLocale, script (native-char regex), audioBase,
storageKey, brand, alpha, voice predicates, lessons, units, unitsIntensive,
sym, vowels, cons, nums, srsSeed, art, latin?, trip?})`. `applyPack(code)`
assigns the active pack to the globals the engine reads (`LESSONS`, `UNITS`,
`SYM`, `NUMS`, `SRS_SEED`, `LESSON_MAP`, `AUDIO_BASE`, `LANG`, …). **The
engine never reads pack consts directly.**

**Language switcher.** `LANG_CATALOG` lists offered languages; the picker is
a dropdown in the HEADER right of the logo (`#lang-switch`,
`paintHomeLangSwitch()`, `LANG_FLAGS` inline-SVG flags; flag-only below
560px). `switchLang(code)` lazy-loads the pack, saves the outgoing language,
applies the pack, reloads state/manifest/voices, `applyBranding()` (hero h1
from `pack.brand`; Intensive tab hidden when `unitsIntensive` is empty) and
rebuilds views. The header mark is the fixed Bhasaly tree — packs do not
brand it. **Storage keys stay `sajilo_*`** (renaming would orphan progress).
`switchLang` refuses to run while the exercise view is active (deliberate).

**State & storage.** `S` is the merged working state. On disk:
`sajilo_global` = cross-language stats (XP, streak, daily, totals, unlocks) +
device prefs (theme/rom/voice/sound/autoNext — never synced);
`sajilo_<code>` = per-language `{done, srs, words}`. `lPick`/`gPick`/
`prefsPick` define the split; `migrateLegacy()` converts the old `sajilo`
blob once (kept as backup); `resetAll` clears every `sajilo*` key. Cloud rows
are `data:{v:2, global, langs:{<code>:{...}}}`; v1 flat rows still merge as
Nepali. **Cloud sync MERGES** (`mergeGlobal`/`mergeLang`: union of done,
more-advanced SRS card, max XP; prefs stay local; active lang stays local) —
never blob-overwrite `S`; push `cloudData()`. XP merging by max (not sum) is
a deliberate idempotency trade-off — don't "fix" it.

**Access codes.** `S.unlocks` (global, cloud-merged by union). Code `ffh`
unlocks the Nepali Intensive (Settings → Additional content; `applyCode`/
`hasIntensive`/`paintUnlock`; `show()` guards direct navigation).

**Modes.** `MODE_CATALOG` / `switchMode` / `paintModeSwitch`: Language
learning vs Religious studies (see Faith mode below). `switchMode` must call
`paintTripTab()` — it writes an inline display that beats stylesheets.

### Lesson schemas

- Lesson: `{id, emoji(unused), title, step, meta, vocab:[[native,rom,gloss]], ex:[...]}`
- Unit: `{n, t, d, lessons:[ids]}`. A topic = 5 lessons:
  `learn → recognize → build → mix → checkpoint`.
- Exercise types: `note{tag,q,body,tip?,eg?}` (eg = `[[native,rom,gloss]]`
  cards; rom slot may be `''`), `mc{q,d?,r?,o,a}`, `fill{q,s,o,a}`,
  `li{q,say,o,a}`, `wb{q,a:[ordered],pool}`, `match{q,pairs}`, `tr{q,a,r,h?}`.
- Weekly test (Intensive): ONE lesson `li_wNtest`, `step:'test'`, `ex:[]` in
  data — `buildTestEx` deals 20 random tap-only questions per attempt; pass =
  80% first-try (`finishTest`); silent (`testMuted`); optional.
- Node symbols come from the `SYM` map keyed by each topic's learn-lesson id.

### Engine invariants (respect these when touching lesson flow)

- Lessons run on a session queue `exQ`: a wrong answer requeues at the end
  until answered correctly. Tests are exempt (fixed 20, first-try scoring).
- **MC/fill/li options are shuffled at render** (`shufOpts`): pack data often
  authors `a:0`, the clone remaps `a`, source data never mutated. Never
  assume slot 0 is correct; key answers by `o[a]`.
- Never use native `confirm()` — use `askConfirm(...)`/`closeConfirm()`.
  All modals close on backdrop click + Escape via `closeModalById`. The
  open-modal class is `.modal-bg.show` (NOT `.open`).
- Streak advances only on real practice (`updateStreak()` in
  `finishQuestion`/`srsGrade`), never on load.
- `speak()`/`speakSlow()` are muted during tests. Speaker icons use
  `spkSVG()` — never the 🔊 emoji.
- Keyboard: 1–9 pick, Enter/Space check/continue, Esc exit (confirm when ≥2
  in); review: Space + 1/2/3.
- Paths scroll to the current node; respect `SMOOTH`
  (prefers-reduced-motion). `lessonById` is a Map lookup (`LESSON_MAP`).
- `finishLesson` calls `addVocab(l.vocab)` on first completion — every taught
  word enters the SM-2 review deck. The lesson path is the INTRODUCTION
  channel; Review is the RETENTION channel (the Duolingo/Anki model).
- CSS: `.section` must keep longhand top/bottom padding (shorthand kills
  `.wrap`'s side gutters — real mobile bug).
- Mascots render via `artMascot()` — **never call `mascotSVG()` at new call
  sites** (it's the Nepali yeti, not the active pack's mascot).

## Standing rules for building or editing a course

1. **AUDIO IS THE GATE.** Check `python3 -m edge_tts --list-voices | grep
   '^<code>-'` before promising any language. Verified to have NO edge-tts
   voice (do not re-investigate without new information): Tibetan, Punjabi,
   Assamese, Odia, Sindhi, Kashmiri, Kyrgyz, Tajik, Turkmen, Dhivehi,
   Bhojpuri, Maithili, Kinyarwanda, Luganda.
2. **Research how the language is actually TAUGHT before designing the zone
   order** — real textbooks/courses (FSI, Georgetown, Peace Corps, Colloquial
   X), not just grammars. Each course is that-language-driven, never a Nepali
   mirror. Content quality is verified by research, not native review:
   cross-check words against multiple sources (Wiktionary, Wikivoyage
   phrasebooks, Omniglot, real course books); prefer colloquial spoken forms;
   flag genuinely unresolved calls in a lesson `note` rather than guessing.
3. **TEACH BEFORE TEST.** The engine never displays `vocab` — teaching
   happens ONLY through `note` exercises. Every learn lesson must introduce
   its words in interleaved notes (real prose + `eg` cards, 2–3 words each)
   BEFORE the quizzes that test them. Content-specific note titles, never
   generic. A generator must emit this shape, and a cold-test measurement
   must run before any course ships. (The ur/uz/jv generator didn't — ur
   cold-tested 98.6% of its vocab and all three needed repair; method and
   measurement traps in HISTORY.md.)
4. **Let content decide topic size** (natural vocab spread, not uniform 5s),
   keep listening (`li`) in every learn lesson (~12–20% of exercises,
   distractors from the same lesson, never two options sharing a
   romanization), and `fill` in build/mix steps.
5. **Romanization fields contain NO native script** (`vocab[1]`, `ex.r` —
   scan with the pack's `script` regex). Roms are ASCII pronunciation
   respellings per the scheme at the top of the pack file.
6. **mc `r` and `d` must never equal/reveal one of that exercise's own
   options** (loanwords collide: menu, film, internet, uncle). `r` belongs
   where options are meanings; ne/km/si/ur carry it on word d-mcs,
   my/lo/ps/mn/bn/uz/jv deliberately don't; letter mcs never (the rom is the
   letter's name).
7. **Node-title register is PROFESSIONAL, standard-curriculum terminology**
   ("The inherent vowel", "Dental & retroflex", "Mixed practice") — never
   cutesy. Descriptive communicative titles and factual cultural ones are
   fine; real linguistics terms are fine.
8. **Course content is secular.** Ministry content exists ONLY in the Nepali
   Intensive and the Religious studies mode. Sensitive topics (suicide/abuse)
   sober, never gamified. No Devanagari typing where Roman suffices
   (tap-based exercises; ≤1 `tr` per day).
9. **Teach-before-test also applies across topics**: don't test vocabulary a
   later topic never taught (compositional forms and no-word-space scripts
   produce false positives — check before "fixing").
   The mirror problem — words taught once and never seen again — has a safe,
   audio-neutral fix: 'Review — which means "X"?' mcs appended to checkpoint
   lessons ≥2 zones later, every option previously-taught recorded vocab,
   numeric targets with numeric distractors, one review per orphan.
   **DONE — all 11 languages, July 2026. Do not re-do it.** Lao piloted it
   (`e40458c2`, 78 reviews, orphans 201→93); `81364e03` then applied it to
   the other ten in one pass — **783 review mcs total** (ne 75, km 95, my 55,
   si 35, ps 75, mn 39, bn 36, ur 112, uz 105, jv 105, lo 78). The three
   generator-built courses carried the deepest debt (ur 195 / uz 178 / jv 185
   reviewable orphans) because the generator never reused vocabulary.
   Guards were verified across all 11 and every `--check` MATCHED.
   Scope was deliberately **words taught in zones 2-8**: zone 1 and zones
   9-12 have no checkpoint ≥2 zones later, so orphans still measure high
   there **by design, not as a defect**. Remaining orphans are also mitigated
   by architecture — `finishLesson` puts every taught word into the SM-2
   deck, so the path is the INTRODUCTION channel and Review is RETENTION.
   Before "fixing" orphan counts again, read HISTORY.md's orphan analysis:
   the number is only meaningful once alphabet letters, numerals and whole
   sentences are separated out, and **distractor appearances must not count
   as recycling** (Lao draws 73.8% of its distractors from the same topic, so
   counting them makes any measurement insensitive to the fix).
   **Register rule (Ruan, July 2026): teach what people actually SAY.**
   Formal "please"-words (ne कृपया, ur برائے مہربانی, lo ກະລຸນາ) are
   RECOGNITION-ONLY — glossed "(formal / signs)", explained in a culture
   note, never production-drilled; politeness is carried by the language's
   real mechanism (verb endings, हजुर, aap). Same for greetings: if the
   textbook greeting isn't the street greeting (my mingalaba vs ne kaung
   la), the note must say so. The July 2026 sweep verified every other
   pack clean on greetings/please/imperatives — don't re-audit without
   new information; details in HISTORY.md "Register relevance pass".
10. **Shipping a new language checklist**: `lang/<code>.js` pack +
    `LANG_CATALOG` entry + secular art + `LANG_FLAGS` flag + audio dir +
    font in stacks if the script needs one + SEO refresh (title/description/
    keywords, JSON-LD `teaches` + `Course` entry) + `gen_landing.py` maps +
    rerun + extractor/generator taught the code. RTL languages: add to
    `RTL_CODES` (faith nav arrows mirror automatically) and check the RTL
    CSS pass (`.wb-answer`, `.fill-sentence`, `.exbig`; any English UI string
    inside an RTL-forced container needs its own `direction:ltr`).
11. **Do ONE language per session, single-threaded.** A parallel-subagent
    attempt burned the usage limit and produced nothing.
12. Keep `<title>` at four languages + "& More" — it's already at Google's
    display limit; do NOT add languages to it. Add everything else to
    description/keywords/JSON-LD.

## Art rules

The full iteration history (what was tried and rolled back, exact
coordinates) is in HISTORY.md — these are the standing rules:

- **No religious buildings or symbols in ANY language's art** (Ruan:
  Christian conviction). Secular imagery only: landscapes, homes, boats,
  animals, plants. No temples/pagodas/stupas/mosques/monks/prayer flags —
  and no cross shapes either, including UI glyphs (the trip `trouble` icon
  is a life ring deliberately). **Exception: real national flags** in
  `LANG_FLAGS` (Cambodia's keeps its Angkor Wat silhouette).
- **NO HUMAN FIGURES in scenery art.** Boats, houses, animals, plants —
  never people.
- A pack overrides art via `art:{hero,band,mascot}` — innerHTML strings for
  `.hero-mtns`/`.pb-mtns` keeping layer classes `orb/far/mid/near` + cloud/
  star groups; every ground path must close along the SVG bottom edge.
  `applyArt()` stamps `data-lang` on `<html>` (drives per-language palettes,
  light + dark, next to the theme vars). **`applyArt` order is load-bearing**
  (clear old art → set data-lang → insert new; iOS Safari repaints on
  palette change — don't "simplify").
- **Palette needs THREE DISTINCT HUE STEPS** (cool far / warm mid /
  saturated near — never three greens). Landmarks sit in a layer that
  CONTRASTS their background.
- **Material colours, not default green**: `--tree` is FOLIAGE ONLY.
  `--wood` boats/posts/beams, `--bark` trunks, `--hide` brown animals,
  `--slate` elephants, `--tyre` wheels/dark openings, `--crimson` accents,
  `--water` where a palette defines it (lo). Pick the real material colour
  first.
- **Title safe zone**: hero — nothing taller than y≈235 in x∈[130,710];
  band — keep x≲770 flat/low. (The title box actually bottoms at y≈185, so
  there's headroom, but stay conservative.)
- **Snow caps are derived, not eyeballed**: for apex (ax,ay), neighbour
  (nx,ny), drop d, base corner = (ax+(nx-ax)*d/(ny-ay), ay+d) kept decimal;
  draw apex→rightBase→jag→leftBase. Re-run the generator
  (`scratchpad/gencaps.py` pattern) whenever a ridge moves; check WIDTHS too
  (>~52px means the peak is too flat — lift the peak, don't shrink the cap).
- **Reusable pieces are drawn once around a local origin and placed with
  `transform="translate(x,y) scale(s)"`.** Grounding rule: translate-y +
  100·scale must land on the near-band surface. (Static sweeps report
  local-origin pieces as "outside the canvas" — false positive.)
- Trees/objects: clusters with real gaps, varied scales — even spacing reads
  as a plantation; assert clearance (>8px) rather than eyeballing overlaps.
- **The art is SIZE-INDEPENDENT** (`width:100%;height:auto`, bottom-anchored)
  — phones see the same picture smaller; use the full 0–1200 canvas; only
  the title safe zone constrains placement. `art-detail` is no longer hidden
  on phones.
- The hero markup exists as **TWO verbatim copies** (home + the faith story
  host view, July 2026 library refactor) and the band as **FOUR** — edit via
  replace_all, apply art fixes to all copies. Faith scene art is duplicated
  in ALL 11 faith packs.
- Sun/orb sits right (cx≈1000–1090), never behind the title.
- Judge icons blown up to ~40px before shipping; at 19px everything looks
  plausible.

## Fonts & scripts

- Google Fonts stacks in `index.html` end with the Noto family each script
  needs; `unicode-range` means learners only download what they render.
- **Burmese** must keep Noto Sans Myanmar in every stack that renders it;
  bare Burmese in notes goes inside `<span class="deva">`.
- **Urdu is Nastaliq** — the `:root[data-lang="ur"]` block overrides every
  native-text surface with Noto Nastaliq Urdu + `line-height:2.05` (tails
  clip otherwise). This includes `.note-eg .egcard .nd`. Naskh (`ps`) needs
  no override beyond the global stacks.
- RTL pass (`ps`, `ur`): word-bank tiles assemble right-to-left,
  `.fill-sentence`/`.exbig` flow rtl; `.wb-ph` and `.from` are forced back
  `ltr`. Faith reader has its own RTL rules; `.fnode-sep` dot hidden for ps
  (looks like ۰).

## Short-term (per-pack phrasebook)

A fourth page next to Learn/Alphabet/Review for short visits; **a pack
feature, not a Bengali special case** — tab/page/flashcards appear only when
the pack defines `trip`. **ALL ELEVEN languages ship it (July 2026)** —
Bengali (14 sections / 151 lines) and Nepali (15/96) hand-built first, then
uz km my si lo ps mn ur jv in one pass (12-15 sections, 70-96 lines, 15-23
frame combos each; per-language spines in the header comment of each pack's
`XX_TRIP` and in the build commits). Prefix-language frames (km mean/som,
lo kho, jv ana) bake the prefix into the items so the suffix engine stays
untouched; gendered frames (ps chere day, ur kitne kaa hai) use items of one
gender to stay grammatical. Lines prefer already-recorded course strings
(reuse ran 55-85%); new strings went through the normal audio pipeline.
**Every language's trip pack must be CONTEXTUALIZED, never cloned** (Ruan):
build it around what a visitor to THAT country actually faces. Nepali's

## Audio system

Recorded MP3s first, device TTS fallback.
- Runtime hash `audioKey(s)` = FNV-1a over UTF-8 bytes (`h=0x811c9dc5`; per
  byte `h^=b; h=(h*0x01000193)&0xFFFFFFFF`; 8-hex). App fetches
  `<audioBase>manifest.json` (array of keys), plays `<key>.mp3` else TTS.
  Lessons prefetch their clips on start.
- Spoken strings = vocab `[0]`, every `say`, mc `d` + correct native option,
  fill's `s` with `___` filled, wb `a.join(' ')`, match `pairs[i][0]`, tr
  `a`, alphabet `VOWELS/CONS/NUMS`, trip lines + assembled frames, faith
  paras + notes. `step:'test'` lessons excluded. **Notes (`body`/`tip`/`eg`)
  and mc `r` are NEVER spoken** — note/r edits are audio-neutral.
- Regenerate strings first: `osascript -l JavaScript
  extract_audio_strings.js <code>` (or `<code>f`; `--check` verifies without
  writing — run it after any pack edit to prove no audio drift). Then
  `python3 generate_audio.py --lang <code>` (`--voice female`, `--rate`
  available; delete the outdir first when switching voice; resumable;
  needs internet). **Never run two generate_audio jobs for one language at
  once** (they collide on `.part` files).
- Known no-clip characters (edge-tts returns nothing; device-TTS fallback,
  NOT bugs): my ဎ, si ඞ ඣ ඦ, bn ং ঃ ঁ, mn Щщ. Never put a bare
  foreign-script character in vocab if the voice cannot say it (Uzbek
  Cyrillic letters live in notes instead).
- Audio dirs sit at the repo top level, next to the HTML.

## Measurement traps (each cost real time once — details in HISTORY.md)

- Tile overflow: `scrollWidth > clientWidth` is the signal; bounding-rect
  comparisons false-positive on every complex script (glyph ink legitimately
  overflows line boxes; use width, not height).
- SVG scenery children report bboxes outside their clipped parent — confirm
  overflow against `document.documentElement.scrollWidth`.
- Supabase `maybeSingle()` returns a ROW; the payload is `row.data` — a stub
  returning the payload directly makes `cloudPull` silently skip merging.
- `switchLang` no-ops while a lesson is open — call `show('home')` first in
  tests. `exitLesson(true)` opens the confirm modal, it is not a force flag.
- Jumping `curE` + `renderEx()` directly leaves `.excard` under a stale
  transform that looks like a layout bug (bypasses `advance()`).
- Computed colours come back as `color(srgb 0.81 …)` 0–1 floats; naive
  contrast scripts read them ~255× too dark. Sanity-check against a
  screenshot before "fixing" any contrast number.
- JS `.length` is UTF-16 code units — a 605K Sinhala file reading as 441K
  chars is not truncation.
- `--check` compares the string SET semantics: an ORDER change (dedup point
  moved) changes the file but not the recordings — diff the set before
  assuming new clips are needed.
- A "set unchanged" result from a loop that errored on a language is
  vacuous — check the loop actually ran every code.
- `window.supabase=undefined` to simulate a missing library —
  `delete window.supabase` doesn't remove the global.
- Static art sweeps: last-40-chars path-closure checks and opacity-attribute
  filters both have documented false positives (HISTORY.md).
- Bulk automation on content (gloss unification, romanization "fixes",
  distractor redraws) has repeatedly produced false matches — **verify with
  a script, edit by hand.** Genuine homographs keep two glosses (छ six/is,
  চিনি know/sugar, یو we-are/1, …).
